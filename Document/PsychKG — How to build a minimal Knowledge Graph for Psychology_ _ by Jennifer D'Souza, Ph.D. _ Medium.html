PsychKG — How to build a minimal Knowledge Graph for Psychology?

From Raw LLM Text Outputs to Validated Structured Information

Jennifer D'Souza, Ph.D.
11 min read
·
Jul 3, 2025

As psychology research expands in complexity and volume, so does the need for structured, machine-readable access to its knowledge. While academic papers remain the main vehicle of scientific communication, they are notoriously hard to search, compare, and integrate — especially across constructs, measures, and methodologies. This post introduces a practical pipeline that transforms unstructured psychology papers into structured knowledge triples using OpenAI’s function calling capability for structured outputs.

The goal: extract psychological constructs and their associated measurement instruments, producing clean, machine-readable outputs that can populate a lightweight knowledge graph.

To make this work, we use Pydantic and OpenAI Function Calling — a streamlined way to define and parse structured outputs directly on the client side. It’s a practical example of how to use OpenAI’s native function calling feature together with Pydantic to generate and validate structured data from research text.

🧩 The Problem: Constructs and Their Measures Are Buried in Text

Psychology research is rich in conceptual structures — constructs like self-esteem, working memory, procrastination, anxiety, rumination, etc. — that are empirically studied via validated measurement scales. However, this construct-measurement relationship is usually embedded in narrative form, making it difficult to reuse for semantic search or meta-analysis.

We want to go from this:

“The paper introduces and utilizes the Extinction Gambling Task (EGT) for studying decision making under extinction risk, providing a structured experimental paradigm to assess…”

To this:

{
  "construct": "decision making under extinction risk",
  "measured_by": "extinction gambling task (egt)",
  "justification": "The paper introduces and utilizes the Extinction Gambling Task (EGT) for studying decision making under extinction risk, providing a structured experimental paradigm to assess participants' choices in scenarios reflecting varying definitions of extinction risks (Keep, Lose, Reset)."
}

🛠️ The Solution: A Minimal Pipeline Using OpenAI + Pydantic

This pipeline has been applied across thousands of full-text psychology papers, enabling the extraction of construct–measurement instrument relationships at scale — unlocking structured insights previously buried in text.

Our approach involves four components:

  1. Defining structured output schemas
  2. Prompting the LLM to extract structured triples
  3. Parsing TEI XML full-text articles as input
  4. Validating and structuring model output using Pydantic

Let’s walk through the Python code that brings this pipeline to life.

📄 Step 1: Define the Structured Output Format

We begin by specifying the structure of the extracted knowledge using simple Python data models. These models capture the key elements we want to extract from each paper.

class PsychTriple(BaseModel):
    construct: str
    measured_by: str
    justification: str

class PsychTripleList(BaseModel):
    extractions: List[PsychTriple]

Each PsychTriple represents a semantic unit in the knowledge graph—linking psychological constructs to their measurement instruments, with justifications.
The PsychTripleList wraps these triples into a list, representing all extractions from a single research paper.

🤖 Step 2: Prompting the Model for Structured Extraction

We define a clear, role-based system prompt to guide the model. The prompt tells the LLM it’s acting as an expert in psychology and knowledge representation, and that it should return a list of construct–measured_by pairs with short justifications.

SYSTEM_PROMPT = '''
You are an expert in psychology and computational knowledge representation. Your task is to extract key scientific information from psychology research articles to build a structured knowledge graph. 

The knowledge graph aims to represent the relationships between psychological **topics or constructs** and their associated **measurement instruments or scales**. Specifically, for each article, you will extract information of the form:

1) "Construct"
2) [Property: "measured by"] -> [Value: "Measure"]

Each article may contain multiple such records. These extractions help build a machine-readable semantic network that connects psychological concepts with their empirical operationalizations.

For each extraction, provide a short justification from the text (1-3 sentences) that supports why this construct was measured by the identified measure.

As far as possible, extract meaningful **phrases** (rather than whole sentences or vague descriptions) as **entities** suitable for inclusion in a knowledge graph for both `construct` and `measured_by` fields.

However, not all articles are relevant to this task. If the article does not discuss psychological constructs and how they are measured (e.g., does not mention constructs, measurement techniques, or instruments), return an empty list `[]`.
'''

We then call the OpenAI API using responses.parse with PsychTripleList as the output format. Here I have used the o3 model which you could replace with your OpenAI model of choice.

response = client.responses.parse(
    model="o3",
    input=[
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": f"Extract the constructs and their measures from the following article:\n{article_text}"},
    ],
    text_format=PsychTripleList
)

This ensures the output is a well-formed, strongly-typed list of triples.

🧼 Step 3: TEI XML Parsing

We assume full-text articles are stored in TEI XML (e.g., output from GROBID). The extract_text_from_tei() function handles text cleanup and formatting:

def extract_text_from_tei(tei_path):
    with open(tei_path, 'r', encoding='utf-8') as file:
        soup = BeautifulSoup(file, 'lxml-xml')
        body = soup.find('text')
        return body.get_text(separator='\n') if body else ''

🧩 Step 4: Structuring and Validating Output with Pydantic

While the OpenAI model generates text, we need to ensure that this text follows a strict, machine-readable structure suitable for downstream applications like knowledge graph population or semantic search. This is where Pydantic comes in.

Pydantic provides the data models (PsychTriple and PsychTripleList) that define the expected structure of the LLM output. When paired with the responses.parse method from the OpenAI Python client, it allows us to automatically validate and convert the raw LLM output into strongly typed Python objects.

Here’s how that looks in code:

from pydantic import BaseModel
from typing import List

class PsychTriple(BaseModel):
    construct: str
    measured_by: str
    justification: str

class PsychTripleList(BaseModel):
    extractions: List[PsychTriple]

Then, during inference:

response = client.responses.parse(
    model="o3",
    input=[
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": f"Extract the constructs and their measures from the following article:\n{article_text}"},
    ],
    text_format=PsychTripleList  # Pydantic schema used here
)

This ensures the returned data conforms to the specified schema: a list of structured triples where each entry is validated for presence and type. If the model’s output deviates from the expected format, the validation will fail — helping catch inconsistencies early and allowing for robust error handling or retry mechanisms.

By enforcing structured output at the schema level, Pydantic acts as a contract between the LLM and downstream consumers, ensuring that what you get is predictable, reliable, and immediately usable for building knowledge graphs or JSON exports.

  • Applications: Lightweight knowledge graphs, semantic search, instrument discovery, QA systems

🕸️ Publishing the PsychKG Subgraph on the ORKG

Now let’s turn to publishing the extracted and validated JSON data as a subgraph on the Open Research Knowledge Graph (ORKG) platform.

The process involves the following steps.

1️⃣ Define the Template

In ORKG, a template represents a semantic schema — a structured model of properties that can be consistently applied to research papers for describing their contributions in a machine-readable way.

2️⃣ Bulk Data Upload: One PsychTripleList Item + One Paper at a Time

Each extracted PsychTripleList corresponds to one paper’s structured contributions. The upload script reads each item and maps it to the ORKG template, linking the extracted constructs, measurements, and justifications to their respective paper metadata.

To do this programmatically we will use relevant functions from the ORKG Python Client https://orkg.readthedocs.io/en/latest/index.html

The complete workflow is in the script upload-to-orkg.py. Let’s unpack the details.

  1. Connect to ORKG and authenticate

To begin, connect to the ORKG API and authenticate using your credentials. You’ll be prompted for the host URL, email, and password:

from orkg import ORKG
from getpass import getpass

host = input("Enter ORKG host URL (e.g., https://www.orkg.org/): ").strip()
email = input("Enter your ORKG email: ").strip()
password = getpass("Enter your ORKG password: ").strip()

print("🔗 Connecting to ORKG...")
orkg = ORKG(host=host, creds=(email, password))
print("✅ Connected.")

📌 Tip: ORKG provides three hosted environments for different purposes:

  • 🧪 Sandbox: https://sandbox.orkg.org/ — for testing data upload workflows
  • 🚧 Incubating: https://incubating.orkg.org/ — for experimenting with platform features under development
  • 🚀 Live: https://orkg.org/ — the production environment where validated data and stable features are published

Use the sandbox for safe trial runs, and the live system only when your data is final and reviewed.

2. Load a Pydantic-validated JSON file (i.e., PsychTripleList)

Each JSON file represents the extracted knowledge for one paper. This is read and parsed:

with open(json_path, 'r', encoding='utf-8') as f:
    data = json.load(f)

for entry in entries:
    c = entry["construct"].strip().lower()
    meas = entry["measured_by"].strip().lower()
    just = entry["justification"].strip()

3. Match to the ORKG Template

Each contribution is created using the Psychology Constructs and Measurements template, identified by its template ID (e.g., R1411854). The script calls the materialize_template() function (https://orkg.readthedocs.io/en/latest/client/templates.html) to fill in this schema programmatically:

template_id = input("Enter the ORKG template ID to use (e.g., R1411854): ").strip()
orkg.templates.materialize_template(template_id)
tp = orkg.templates

4. Create the Contribution for Each PsychTriple

The script loops through each triple and creates resources for the construct and measurement (if they don’t already exist), then fills in the justification field. For example:


for entry in entries:
    c = entry["construct"].strip().lower()
    meas = entry["measured_by"].strip().lower()
    just = entry["justification"].strip()

    for label in [c, meas]:
        if label and label not in resource_cache:
            try:
                response = orkg.resources.find_or_add(label=label)
                resource_id = response.content["id"]
                resource_cache[label] = resource_id
                print(f"✅ Added/Found: '{label}' → {resource_id}")
                save_resource_cache(resource_cache, cache_path)
            except Exception as e:
                print(f"❌ Failed to create/find resource for '{label}': {e}")

    c_id = resource_cache.get(c)
    meas_id = resource_cache.get(meas)

    if not c_id or not meas_id:
        print(f"⚠️ Missing resource for '{c}' or '{meas}'")
        continue

    c = tp.psychology_constructs_and_measurements(
        label=f"contribution {counter}",
        topic_or_construct=OID(toc_id),
        measured_by=OID(meas_id),
        justification=just
    )
    contributions.append(c)

    resource_entries.append({
        "topic_or_construct": toc_id,
        "measured_by": meas_id,
        "justification": just
    })

    print(f"✅ Created contribution {counter}")
    counter += 1

5. Link to the Paper Metadata

The script links each contribution to the corresponding paper resource in ORKG. The user is prompted (or a mapping is provided) for the paper’s title, DOI, or existing ORKG resource ID.

paper = {
    "predicates": [],
    "paper": {
        "title": metadata["title"],
        "doi": metadata["doi"],
        "authors": metadata["authors"],
        "publicationMonth": metadata["publicationMonth"],
        "publicationYear": metadata["publicationYear"],
        "publishedIn": metadata["publishedIn"],
        "researchField": "R343", #resource id for the research field Psychology on the ORKG https://orkg.org/fields/R343/Psychology
        "contributions": [c.template_dict['resource'] for c in contributions]
    }
}

try:
    response = orkg.papers.add(params=paper)
    paper_id = response.content["id"]
    log_uploaded_paper_detailed(paper_log_detailed_path, metadata["title"], paper_id)
    append_structured_log(structured_log_path, paper_id, resource_entries)
    print(f"📄 Paper uploaded: {metadata['title']} → {paper_id}")
except Exception as e:
    print(f"❌ Failed to upload paper: {e}")

6. Repeat for Each Paper

The script processes each JSON file in the directory — each representing one paper — uploading all its extracted triples as a single contribution.

This approach ensures each extraction becomes a searchable, semantically structured entry in the ORKG. Over time, these micro-contributions accumulate into a rich, navigable knowledge graph of psychological constructs and their empirical operationalizations.

This end-to-end workflow — from full-text parsing to validated triple extraction and knowledge graph publication — not only demonstrates technical feasibility, but also showcases how general-purpose LLMs can be adapted for domain-specific, structured scientific metadata generation at scale. By publishing this data as FAIR, semantically linked contributions in the ORKG, we make psychological research more searchable, comparable, and reusable — paving the way for more systematic reviews, instrument discovery, and large-scale meta-analyses.

🧠 Why It Matters

This workflow lowers the barrier to building domain-specific knowledge graphs. Instead of training a custom NLP pipeline or building a rule-based system, we delegate the task to a general-purpose LLM guided by a schema and expert prompt.

In doing so, we make empirical psychological knowledge — once locked in prose — available for structured reasoning and reuse.

🚀🧵 Next Steps

Here are a few recommendations to build on this work:

  • Add support for gold-standard metadata extraction (authors, title, abstract)
  • Enrich the schema with additional properties with a tool like schema-miner https://github.com/sciknoworg/schema-miner over a large-scale collection of the publications
  • Explore integration with LLM-powered interfaces (e.g., chat-based exploration or semantic QA) to make the knowledge graph more accessible to non-expert users
  • Develop autonomous agents that continuously monitor new psychology publications, extract structured triples, and suggest updates to the graph
  • Implement agent workflows for validation (e.g., human-in-the-loop curation) and refinement (e.g., schema expansion, relation alignment)
  • Investigate multi-agent collaboration setups where one agent extracts, another verifies, and a third links entries to external ontologies like UMLS or MeSH
