How I Get LLMs on Hugging Face to Speak Structured Data? The Two-Library Magic (Instructor + Pydantic)

Building MVP Knowledge Graphs from Research Articles

Jennifer D'Souza, Ph.D.
6 min read
·
Jul 3, 2025

📍 The Problem: LLMs Speak Text. I Want Structure.

I work a lot with research papers. And when I use large language models (LLMs) to extract knowledge from them — whether it’s entities, relationships, or claims — I don’t want free-form text. I want clean, structured data I can plug into a knowledge graph, a database, or an analysis pipeline.

But LLMs, especially open-weights ones on Hugging Face, don’t natively speak JSON. And when they try, it’s often wrong: missing commas, wrong fields, stray quotes, invalid arrays. This makes downstream parsing brittle and painful.

🤔 So what’s the fix?

1. 🧭 Instructor

Instructor transforms any Hugging Face text generation model into a structured output generator. With just one line:

results = llm(prompt, output_type=List[PsychTriple])

Instructor:

  • 📜 Formats the prompt to include JSON schema hints
  • ✅ Parses and validates the model output
  • 🔁 Retries automatically if the output is malformed or incomplete

It turns a generic language model into something that behaves more like an API client for structured responses.

2. 🧱 Pydantic

Pydantic is a Python library for defining and validating structured data with types and constraints. Think of it as JSON Schema, but in Pythonic form.

Here’s the schema I use for extracting psychological triples:

class PsychTriple(BaseModel):
    topic_or_construct: str
    measured_by: str
    justification: str

This gives me:

  • ⚖️ Type validation
  • ✅ Auto-parsing from model output
  • 🔍 Clear error messages when something goes wrong

And because Instructor directly integrates with Pydantic, I can just say:

output_type=List[PsychTriple]

…and the LLM is bound to that schema. No post-processing needed.

3. 🔮 The Magic Duo: Instructor + Pydantic

Together, these libraries let you build a typed interface on top of open-source language models.

You get:

  • The openness and flexibility of Hugging Face models
  • The structure enforcement of Pydantic
  • The automation and retry logic of Instructor

Result: A modular, robust pipeline for structured information extraction from unstructured text.

4. 🔍 Use Case: Extracting Knowledge Triples from Psychology Papers

Let’s walk through the full script I use to extract structured information from .xml psychology articles encoded in the TEI format. The goal is to populate a lightweight knowledge graph with the relationships between psychological constructs and their measurement instruments, along with a justification from the paper.

🔧 Start off with a small set of import statements for the relevant libraries

import os
import json
from pathlib import Path
from typing import List
from bs4 import BeautifulSoup

from pydantic import BaseModel, ValidationError
from transformers import AutoTokenizer, AutoModelForCausalLM, pipeline
from instructor import Instructor, patch_instructor
from tqdm import tqdm
import torch

🧱 Step 1: Define the schema

class PsychTriple(BaseModel):
    topic_or_construct: str
    measured_by: str
    justification: str

📄 Step 2: Extract text from TEI XML

def extract_text_from_tei_xml(tei_path: str) -> str:
    try:
        with open(tei_path, 'r', encoding='utf-8') as file:
            soup = BeautifulSoup(file, 'lxml-xml')
            body = soup.find('text')
            return body.get_text(separator='\n') if body else ''
    except Exception as e:
        print(f"Error parsing {tei_path}: {e}")
        return ""

✍️ Step 3: Build the prompt with domain-specific instructions

def build_prompt(text: str) -> str:
    return f"""
You are an expert in psychology and computational knowledge representation. Your task is to extract key scientific information from psychology research articles to build a structured knowledge graph.

The knowledge graph aims to represent the relationships between psychological **topics or constructs** and their associated **measurement instruments or scales**. Specifically, for each article, extract information in the form of triples that capture:

1) The psychological topic or construct being studied  
2) The measurement instrument or scale used to assess it  
3) A brief justification (1–3 sentences) from the article text supporting this measurement link

Guidelines:
- Extract meaningful **phrases** (not full sentences or vague descriptions) for both `topic_or_construct` and `measured_by`, suitable for inclusion in a knowledge graph.
- Include a short justification for each extraction that clearly supports the connection.
- If the article does not discuss psychological constructs and how they are measured (e.g., no mention of constructs, instruments, or scales), return an empty list `[]`.

Input Paper:
\"\"\"{text}\"\"\"

Output: Provide your response as a JSON list in the following format:

[
  {{
    "topic_or_construct": "...",
    "measured_by": "...",
    "justification": "..."
  }},
  ...
]
""".strip()

This prompt guides the LLM to extract structured triples — only if the article contains relevant content.

📤 Step 4: Process each file using Instructor

def process_file(file_path: str, prompt_dir: str, output_dir: str, llm: Instructor) -> bool:
    text = extract_text_from_tei_xml(file_path)
    if not text:
        print(f"⚠️ Skipping empty or malformed text in {file_path}")
        return False

    prompt = build_prompt(text[:100000])
    prompt_path = Path(prompt_dir) / (Path(file_path).stem + ".prompt.txt")
    output_path = Path(output_dir) / (Path(file_path).stem + ".json")

    with open(prompt_path, "w", encoding="utf-8") as f:
        f.write(prompt)

    try:
        results = llm(prompt, output_type=List[PsychTriple])
        if not results:
            print(f"✅ {file_path} | Extracted 0 triples")
            return False

        with open(output_path, "w", encoding="utf-8") as f:
            json.dump([r.model_dump() for r in results], f, indent=2)
        print(f"✅ {file_path} | Extracted {len(results)} triples")
        return True
    except ValidationError as ve:
        print(f"❌ Validation failed for {file_path}:\n{ve}")
    except Exception as e:
        print(f"❌ Failed to process {file_path}: {e}")
    return False

Prompts and structured outputs are saved per file, and invalid or irrelevant files are gracefully skipped.

🚀 Step 5: Run the pipeline with an LLM on Hugging Face

def main():
    input_dir = input("Enter input directory with .xml files: ").strip()
    prompt_dir = input("Enter directory to save prompts: ").strip()
    output_dir = input("Enter directory to save JSON outputs: ").strip()
    model_name = input("Enter Hugging Face model name (e.g., Qwen/Qwen2.5-72B-Instruct): ").strip()

    for d in [input_dir, prompt_dir, output_dir]:
        os.makedirs(d, exist_ok=True)

    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(
        model_name,
        device_map="auto",
        torch_dtype=torch.float16 if torch.cuda.is_available() else torch.float32
    )

    text_gen_pipeline = pipeline(
        "text-generation",
        model=model,
        tokenizer=tokenizer,
        max_new_tokens=8000,
        return_full_text=False
    )

    llm = Instructor(text_gen_pipeline)

    files = list(Path(input_dir).glob("*.xml"))
    if not files:
        print(f"⚠️ No .xml files found in {input_dir}")
        return

    total_articles = 0
    satisfied_articles = 0

    for xml_file in tqdm(files, desc="Processing TEI XML files"):
        total_articles += 1
        success = process_file(str(xml_file), prompt_dir, output_dir, llm)
        if success:
            satisfied_articles += 1

    print("\n=== Extraction Summary ===")
    print(f"Total articles processed: {total_articles}")
    print(f"Articles with extracted constructs and measures: {satisfied_articles}")
    print(f"Articles without relevant content: {total_articles - satisfied_articles}")

🪷 But Wait — What Is Instructor Actually Doing?

You might wonder: Couldn’t I do this with just a prompt, a for loop, and some json.loads() calls?

Here’s what Instructor is really doing for you behind the scenes:

1. Prompt Engineering with Schema Injection

It takes your Pydantic model (e.g., List[PsychTriple]) and:

  • Converts it into a schema hint
  • Embeds this schema into the prompt automatically
  • Encourages the LLM to emit structured output that matches

2. Parsing + Validation

Once the LLM responds, Instructor:

  • Parses the output into JSON
  • Validates every record against your schema using Pydantic
  • If it doesn’t match (e.g., wrong types, missing fields), it raises errors

3. Automatic Retries

If the model output is malformed or doesn’t pass validation, Instructor:

  • Automatically re-prompts the model
  • Optionally adds error hints (if using patch_instructor)
  • Retries multiple times until a valid response is received or the retry limit is reached
